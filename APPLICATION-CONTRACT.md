# Public application contract v1

`application` is the **raw object** in `application.example.json`, not the exported browser draft envelope. The pinned validator is `scripts/forge-application-model.mjs`. It validates syntax, not identity, ownership, endpoint availability, chain state, pricing compatibility or eligibility. It never visits submitted endpoints.

Required profile fields: `name` (80 characters), `summary` (1200), `ownerWallet` (public EVM/Base address, 0x + 40 hex characters), `techStack` (1–20 entries, 48 characters each), `requestedCategory` (`community` or `partner`) and `services` (1–8 entries). `projectName` (80), `website`, `x`, `telegram` are optional, but at least one public contact URL is required. Social URLs must be profile URLs on x.com/twitter.com or t.me.

Each service requires `name` (80), `description` (800), `protocol` (`mcp`, `rest`, `a2a`), `endpoint`, `pricing` (`free`, `ape-quote`), `unit` (100), `input` (800), `output` (800) and `support` URL. `ape-quote` is descriptive only; it does not request or perform a payment. URL fields allow up to 2048 characters, HTTPS public-format DNS names only, no embedded credentials, IP literals or reserved/local hostnames. Endpoints cannot include fragments. Unknown fields are rejected.

Maximum raw profile and prepared issue body: **32768 UTF-8 bytes** each. The MCP JSON-RPC line limit is 65536 bytes; queued requests are bounded. Oversized/invalid inputs cause no submission. A normalized profile is hashed with SHA-256 to form `forge-v1-<64 lowercase hex characters>`. It is embedded as an exact HTML-comment marker in the public issue. The marker is a reconciliation aid, not an ownership signature or atomic idempotency key.

Only `forge_submit_application` can mutate remote state. It requires the exact prepared `requestId` and `publicProfileConsent: true`; it first checks the fixed repository and searches up to 100 of the authenticated applicant's issues for the exact marker. It creates at most one issue per request per server process. The body is written to a private temporary directory (0700, file 0600), passed to `gh issue create --body-file`, then removed. GitHub CLI is invoked without a shell; the destination is fixed to `https://github.com/chaoscrewweb3-prog/apeforge-skill`. No arbitrary repository, URL, command, labels or executable template is accepted.

A confirmed receipt is `{state:"submitted-for-review",issueUrl:"https://github.com/chaoscrewweb3-prog/apeforge-skill/issues/N",registrationState:"not-registered",membershipState:"not-approved",...}`. Existing matches are returned without creation. Failed or unrecognized creation receipts are **ambiguous**, with a saved `requestId`; do not automatically retry. Search indexing delay and concurrent processes/accounts mean duplicates remain possible. `forge_reconcile_application` is read-only, bounded and may return no result even after successful creation. Closed issues remain included. The kit does not implement update/CAS, privileged approvals, server registration, cookies, bearer agent authentication, wallet signing or transactions.
